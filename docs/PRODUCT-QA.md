# Crate product QA

Developed by Ajnas N B

Audit date: 17 October 2026. This is a bounded product audit, not a claim of complete accessibility conformance, customer validation, live Qloo success, or a probability of winning.

## Findings and small fixes

| Priority | Flow | Evidence and impact | Change |
| --- | --- | --- | --- |
| P1 | Dialog access | The shared native dialog had no accessible title, and replacing its contents for entity search could leave focus without a useful destination. | Link the dialog to its visible heading, focus that heading on each modal change, preserve the original trigger, and restore it on close. Native `showModal()` retains modal behavior. |
| P1 | CSV error recovery | Importing from the stock dialog could put its error in the inert background page. | Repeat the current error inside the open dialog with an explicit dismiss control. Do not discard the existing inventory on parse failure. |
| P2 | Source comprehension | A configured credential was described as an available live connection before successful API validation. | Distinguish configured credentials, selected live setup, and an actual live ranking snapshot. Retain the original plan's source until replacement succeeds. |
| P2 | Touch and feedback | Small icon controls and visual-only toggle states created avoidable friction; search success had no result-count announcement. | Increase target sizes, add pressed states, announce plan/search status, and retain text errors. Add a keyboard skip link. |
| P2 | Imported cover colors | Imported dark hex colors could produce black title text on a dark cover. | Choose black or white text by calculated contrast. Sample covers retain their existing appearance. |
| P2 | Local edits and invalid inputs | Reload behavior was not prominent; incomplete programme names could produce poor labels. | Explain that edits apply immediately and reset on reload, provide current-stock CSV download, reject empty programme fields before planning, flag invalid reserves, and avoid negative availability displays. |

No visual redesign, dependency addition, external contact, or persistent stock database was introduced.

## Route and flow map

One page, `/`: first visit → inspect labeled sample stock → Pack the stalls → review selections → optionally pin/veto/edit quantities or programmes → repair or rebalance → export. Stock, programme, evidence, entity matching, and About are native dialog views. There is no account, payment, or forced setup wall. Live mode additionally requires server configuration and manual entity confirmation. Reload intentionally resets the local desk; stock CSV provides an explicit way to retain inventory.

## Verification and static scan triage

- The skill's static scanner ran against the project: 96 files, P0=0, P1=34, P2=36. Most signals came from unused starter UI components and runtime type files, not this rendered desk. No blanket “70 product defects” claim is made.
- A scoped scan of `app/` after initial fixes scanned ten files and reported one signal: suppression of a heading's focus outline. That unnecessary suppression was removed. Button-type and input-autofill signals were addressed. The final scoped scan of ten files reported P0=0, P1=0, P2=0, P3=0. This is a heuristic scan, not an accessibility certification.
- TypeScript AST inspection found 31 explicit button types, exactly one submit control, one native dialog, five conditional titled views, a skip link, and no clickable generic containers.
- Final full TypeScript (`tsc --noEmit`) and frontend ESLint checks passed after the cover-contrast and reserve-display adjustments. These checks do not imply a successful production deployment.
- CSV/export suite: thirteen tests passed in this audit run. After the invalid-reserve rule and seeded comparison inputs were reconciled, an independent final run passed all 54 automated tests. This does not establish live API or customer results.

There was no live Qloo call, customer pilot, screen-reader session, axe run, Lighthouse report, physical print-pagination check, or field Core Web Vitals measurement in this pass. Those limits remain open rather than being replaced by a numerical product-quality score.
