# Crate readiness and recovery review

Developed by Ajnas N B

Historical review, October 17. The subsequent [October 22 live verification](LIVE-QLOO.md) closes the technical access, mapping and live-tool gates. Reader usefulness and customer outcomes remain unproved.

This review reuses the sixteen concept and product ledgers. It is a bounded product critique and observed software check, not customer research, sixteen new experiments or a winning-probability estimate.

## Proposition against the judging criteria

| Criterion | What the prototype demonstrates | What remains unproved |
| --- | --- | --- |
| Technological implementation | Exact shared-stock allocation, minimal repair, server-side Qloo contracts and MCP dispatch. The current 56-test suite uses mocks for Qloo. | Genuine title/author matches, inventory-restricted rankings, meaningful programme differences and successful live external-tool planning. |
| Design | A coherent packing desk preserves stock, reserves and editorial decisions. The recovery gap below now has an explicit inspection path. | A real bookseller completing the workflow without coaching, including live setup and usable physical exports. |
| Potential impact | Two separately staffed stalls leaving simultaneously cannot reuse the same physical copy. | Frequency of this problem, adoption, time savings and sales effects. Existing public pop-up examples are not customer validation. |
| Quality of the idea | Cultural briefs guide a bounded stock allocation rather than an unconstrained reading list. | Whether Qloo adds useful distinctions for a small available inventory. A correct allocator alone cannot establish that cultural contribution. |

The next decisive work remains live coverage and usefulness. Broader scope, more animation and repeated unchanged checks would not establish those claims.

## Verification

- Before the first pack, pinned single-copy Kindred to both stalls. Packing failed visibly; the new panel exposed both synthetic ranking lists and their 12/12 coverage, with no manifest created.
- Followed Review stock and pins, removed the conflicting pin and packed eight placements. Export became available.
- Removed Kindred stock while its remaining pin required a copy. Repair failed. The latest check was inspectable, while the original source label and opened 1,173-character snapshot JSON remained exactly unchanged. Export and print stayed disabled.
- The recovery shortcut focuses the stock dialog heading; Escape returns focus to See the evidence. The narrow-layout check found no horizontal dialog overflow. Selected desktop and narrow screenshots were inspected.
- TypeScript, targeted ESLint and the production build passed. The scoped scanner found zero static signals in ten application files. Repository-wide scanner signals included ignored runtime material and unused starter components; they are not fifty-one confirmed product defects.
- Planner and API logic are unchanged, so the previously passing 56-test suite was not repeated for this presentation-only correction.

Screenshots remain in the parent Crate evidence directory as `crate-first-failure-evidence.jpg`, `crate-later-failure-evidence.jpg` and `crate-recovery-mobile.jpg`. Partial/zero live responses and real upstream warning display still require the authorized Qloo credential; the completed browser checks used honestly labeled simulation.
